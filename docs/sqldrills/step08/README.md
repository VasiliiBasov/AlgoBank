> Теория блока: `THEORY.md` (карта чтения внутри).

**Цель:** уверенно писать `INNER/LEFT/RIGHT JOIN` без гугла — это вторая
половина требования «SQL (SELECT, JOIN)» из вакансии EGAR. `FULL OUTER JOIN` —
в теории (§5 THEORY): наш движок-стенд H2 2.4 его **не поддерживает вообще**
(проверено в живую: `Syntax error` и на `FULL OUTER JOIN`, и на `FULL JOIN`;
в PostgreSQL/Oracle — есть, эмуляция — `LEFT … UNION ALL … правый anti-join`).
Отдельные фокусы: **поведение NULL при JOIN**, **эквивалентность LEFT ↔ RIGHT**,
**условие в ON vs WHERE** у OUTER JOIN.

## Схема и данные

## Шпаргалка-минимум (без ответов на задачи)

```sql
SELECT a.owner_name, t.amount_minor
FROM account a
JOIN transactions t ON t.account_id = a.id;   -- INNER: только пары «счёт+его транзакция»

-- LEFT : все счета; где транзакций нет — колонки t.* = NULL
-- RIGHT: зеркало LEFT (переверни FROM); FULL: строки обеих сторон + NULL-ы
--   (⚠ H2 2.4 FULL не знает — теория §5; в PostgreSQL писать FULL [OUTER] JOIN)
-- ANTI-JOIN: LEFT JOIN ... WHERE t.id IS NULL  → «счета без транзакций»
-- Условие в ON (для OUTER JOIN) ≠ условие в WHERE: ON решает «что считать парой»,
-- WHERE отфильтровывает уже построенный результат (у INNER — эквивалентны!)
-- NULL не равен ничему, даже NULL: t.x = a.x никогда не сматчит NULL-ы
ORDER BY col NULLS LAST;   -- явная позиция NULL (H2 поддерживает NULLS FIRST/LAST)
```

## Задачи

Правила: **один `SELECT` на файл**, **без подзапросов** (тема блока 10),
явный список колонок (без `*`), осознанный `ORDER BY` — порядок строк сверяется точно.
Файл: `src/main/resources/sqldrills/step08/qNN.sql`.

### Q1 — `q01.sql` — INNER JOIN
Все транзакции **с именем владельца**: `id` транзакции, `owner_name`, `amount_minor`;
по `id` транзакции. *(10 строк; Анны нет — почему?)*

| id | owner_name     | amount_minor |
|----|----------------|--------------|
| 1  | Иван Петров    | 100000       |
| 2  | Иван Петров    | -4500        |
| …  | …              | …            |
| 10 | Иван Петров    | -450         |

### Q2 — `q02.sql` — INNER + WHERE
Транзакции **Ивана Петрова**: `id`, `amount_minor`, `description`; по `id`.
*(4 строки: 1, 2, 3, 10. Фильтр по имени, не по id счёта!)*

### Q3 — `q03.sql` — LEFT JOIN
**Все счета** (включая пустые) с их транзакциями: `owner_name`, `id` транзакции,
`amount_minor`; сортировка по `id` счёта, внутри — по `id` транзакции.

*(11 строк: 10 с данными + Анна с двумя NULL в конце.)*

### Q4 — `q04.sql` — ANTI-JOIN
Счета **без транзакций**: `id`, `owner_name`. Ровно одной строкой — через
`LEFT JOIN … IS NULL`, не через NOT IN.

| id | owner_name   |
|----|--------------|
| 4  | Анна Козлова |

### Q5 — `q05.sql` — RIGHT JOIN
Тот же результат, что в Q3 (11 строк, тот же порядок), **но написанный через
`RIGHT JOIN`** — таблицы перевернуты местами. Цель: почувствовать эквивалентность.

### Q6 — `q06.sql` — LEFT JOIN + условие в ON (ON vs WHERE!)
Все счета + их **положительные** транзакции: соединение `t.account_id = a.id
AND t.amount_minor > 0` — положительность строго **в ON, не в WHERE**.
Перенесёшь в WHERE — Анна выпадет вместе со всеми «пустыми» строками:
WHERE по правой таблице превращает LEFT в INNER (теория §2). Это **главная
ловушка собесов** по JOIN.
Колонки: `owner_name`, `id` транзакции, `amount_minor`; порядок — `id` счёта,
затем `id` транзакции.

| owner_name      | id   | amount_minor |
|-----------------|------|--------------|
| Иван Петров     | 1    | 100000       |
| Мария Сидорова  | 4    | 200000       |
| Мария Сидорова  | 6    | 35000        |
| Олег Смирнов    | 9    | 1000         |
| Анна Козлова    | NULL | NULL         |

*(5 строк. Контрольный вопрос на зачёте: сколько строк станет, если то же
условие написать в WHERE? Посчитай в уме: 4.)*

### Q7 — `q07.sql` — SELF-JOIN + мульти-JOIN
Найди пару транзакций-«двойников»: **одинаковая сумма, разные счета**.
Колонки: `id` первой, имя её владельца, `id` второй, имя её владельца, сумма.
Пару не дублируй зеркально (условие `t1.id < t2.id`). Это **4 таблицы** в FROM:
`t1 JOIN t2`, плюс `account` дважды (два алиаса!).

| t1.id | owner1       | t2.id | owner2      | amount_minor |
|-------|--------------|-------|-------------|--------------|
| 8     | Олег Смирнов | 10    | Иван Петров | -450         |

### Q8 — `q08.sql` — JOIN + фильтр + порядок
Транзакции **крупнее 10000** (минорных): `owner_name`, `id`, `amount_minor`,
`balance_minor` владельца; по убыванию суммы. *(3 строки: 200000 Мария,
100000 Иван, 35000 Мария — баланс Марии повторится, это нормально.)*
