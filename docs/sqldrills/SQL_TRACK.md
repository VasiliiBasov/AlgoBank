# 🗄 SQL-поток AlgoBank

> Постоянный SQL-поток курса: идёт **внутри шагов 7–26** наравне с algo-задачами —
> те же ритуалы: красные тесты → решение учеником → ревью с критикой и разбором →
> баллы → устный зачёт. Родился как срочный фикс пробела из mock-интервью 25.09
> (SQL 20/100: перепутан INNER/LEFT, запрос не написан); требования вакансий:
> EGAR — «SQL (SELECT, JOIN)», СПИИРАН — «реляционная модель, базовый синтаксис SQL».

## Модель (та же, что у алгозадач)

- **SQL-блок в каждом шаге**: обычно 2–3 задачи (ядро шагов 7–11 — блоки 4–12 задач,
  чтобы досрочно закрыть фундамент под собеседования). Тема блока подобрана к теме шага.
- **SQL пишет только ученик** (правило №5): один файл = один запрос (`qNN.sql`).
  Ментор пишет инфраструктуру, постановки, тесты с ожиданиями, разборы.
- Ритм: SQL-слот 20–30 минут **в рамках шага**, не вместо основного кода шага.
- Баллы и провалы попадают в LEARNING_LOG/STATS и ротацию разминок — как у алгозадач.

## Где что лежит (по аналогии с ru.algobank.algo.stepNN)

```
src/main/resources/sqldrills/
├── seed/V900__sqldrill_seed.sql      ← фикстуры (Flyway, только профиль sqldrill)
└── stepNN/qNN.sql                    ← РЕШАЕТ УЧЕНИК (один запрос на файл)
src/test/java/ru/algobank/sqldrills/
├── SqlDrillDb.java                   ← чистая H2 на каждый запрос: db/migration + seed
├── SqlDrillRunner.java               ← читает qNN.sql, чистит '--', требует один SELECT,
│                                       сверяет результат (порядок строк и колонки важны)
└── stepNN/SqlStepNNTest.java         ← приёмочные тесты блока (ожидания зашиты)
docs/sqldrills/
├── SQL_TRACK.md                      ← этот файл (мета + карта + ритуалы)
└── stepNN/README.md                  ← теория-минимум + постановки + ожидаемые таблицы
```

## Как работать

```powershell
# 1. Автопроверка блока шага (красная, пока не решён — это и есть учебный цикл):
mvn -Dtest=SqlStepNNTest "-Dsqldrills=on" test        # сейчас: SqlStep07Test

#    Гейт -Dsqldrills=on (@EnabledIfSystemProperty) — осознанный: без него дрели
#    пропускаются, и основной прогон/GitHub CI остаются зелёными, пока блок не сдан.

# 2. H2 console — для свободных экспериментов с данными:
mvn spring-boot:run "-Dspring-boot.run.profiles=sqldrill"
#    http://localhost:8082/h2-console · JDBC URL: jdbc:h2:mem:sqldrills · sa / (пусто)

# 3. Пишешь запрос в src/main/resources/sqldrills/stepNN/qNN.sql,
#    прогоняешь тест, читаешь diff «expected vs actual» в сообщении теста.
```

Если русские сообщения тестов в PowerShell выглядят «кракозябрами» — перед прогоном
выполни `chcp 65001` (в IDEA при запуске тестов такой проблемы нет).

## Оценка блока (100 баллов)

- Задачи: **80 баллов** пропорционально зелёным (зелёные/N × 80).
- Устный зачёт (ловушки по теме блока): **до 20 баллов**.
- Блок зачтён при **N/N зелёных** и **зачёте ≥ 80/100**; провалы — в ротацию разминок.
- Оценки фиксируются в LEARNING_LOG (запись сессии) и STATS.md — как у алгозадач.

## ⏱ Учёт времени (сегменты внутри сессии)

Команды сессии прежние: «начинаю обучение» / «пауза» / «продолжим» / «закончили на
сегодня». Дополнение — **переключатель активности**:

- **«на SQL»** / **«на шаг»** («на код») — ментор фиксирует `Get-Date`, закрывает
  предыдущий сегмент, открывает новый. Не сказал ничего — действует последний
  объявленный сегмент; при неоднозначности ментор спросит один раз.
- В `STATS.md` SQL-сегмент — **отдельная строка** с меткой 🗄
  (например, «🗄 SQL-блок 7: q01–q05»). Время шага = сумма его сегментов
  (код + algo + 🗄 SQL).
- Сводный итог по SQL-потоку (часы и баллы по блокам) — в `STATS.md`, раздел
  «🗄 SQL-поток»: оттуда виден объём практики для собес-нарратива.
- Правило #8 действует: время только через `Get-Date`, без коэффициентов.

## Ритуал сдачи блока (как у алгозадач)

1. Зелёные тесты (`-Dsqldrills=on`).
2. **Ревью ментора** по файлам qNN.sql: читаемость, явный список колонок (без `*`,
   если его не просили), осознанный ORDER BY, отсутствие лишнего (`DISTINCT` «на всякий
   случай» — повод для вопроса).
3. Разбор ошибок в сессии + устный зачёт.
4. Баллы → журнал/дашборд.
5. **Снятие гейта**: ментор убирает `@EnabledIfSystemProperty` с `SqlStepNNTest` —
   тесты навсегда вливаются в основной прогон и CI как регрессионная защита.
